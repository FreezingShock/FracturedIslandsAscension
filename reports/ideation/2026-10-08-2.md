# FI:A ideation - 2026-10-08 (second batch)

Assumptions: a report for 2026-10-08 already exists on `claude/fia-reports` (Elite Variants, Workbench & Recipes, Island Merchant, Gathering Nodes). To avoid overwriting it this batch is `2026-10-08-2.md`, and none of those four is repeated. Vault unavailable. Keys checked by grep: Q/R/T/E/C/G bound in Client; abilities use RMB/Z/X/C/V. No idea below adds a key.

## What I noticed
- **Armor has no set concept.** `Items/Defs/Armor.lua` has a full iron set (helmet/chestplate/leggings/boots, flat `stats` only) and `Define.lua` has no `set` field, so wearing four matching pieces gives nothing beyond the sum. `AttributeStatManager.ApplySource` already takes arbitrary named sources.
- **A consumable category exists but nothing uses it.** `Define.lua` `CATEGORY_DEFAULTS.consumable` (maxStack 999, equippable) is defined, while `Items/Defs/*` has zero consumables, and `AttributeStatManager.AddTempBonus(player, attr, mode, amount, duration)` plus `ListTempBonuses` is there with no gameplay caller.
- **Kills are not remembered.** `LootService.reward` (3.60-3.63) pays XP, drops and Coins per kill, and 7 enemy types exist (`EnemyConfig.enemies`), but no per-enemy kill count is saved, so the new mobs have no long-term hook. `CollectionRewards.register` is a ready-made reward registry.
- **Bosses are scaffolded but absent.** `EnemyConfig.enemies.rustblade_knight.phases = nil -- RESERVED`, plus the AI state machine and attack kinds (3.74.1), the tags (3.71/3.72) and the death FX (3.73) are all in place; `ZoneConfig.ZONES` is still empty.

## Ideas

### 1. Armor Set Bonuses (S)
- **Pitch:** Wear all four pieces of a set and a bonus lights up, shown as a "Full Set" line on every piece's tooltip. Mixing sets still works, it just forfeits the bonus.
- **Why now:** The 4-piece iron set and 4 filler armors (3.70.0) exist, and equipment already flows through `AttributeStatManager.ApplyEquipment`; players have no reason to prefer a matched set.
- **Spec:** Goal: items declare a `set` id; when N pieces of one set are equipped the set's tier bonuses are applied as an attribute source. Files: `Shared/Modules/Inventory/EquipmentConfig.lua` (sets library), `Items/Defs/Armor.lua` (add `set = "iron"`), `Items/Define.lua` (pass `set` through), `Server/Inventory/EquipmentService.lua` (count equipped pieces per set, hand extra entries to `ApplyEquipment` with a `set:<id>` source id). Config: library `EquipmentConfig.sets.iron = { name = "Iron", color = "#AAAAAA", bonuses = { [2] = { stats = { Defense = 10 } }, [4] = { stats = { Defense = 40, Strength = 10 }, text = "Sturdy as a wall." } } }` -> type `EquipmentConfig.setDefaults = { countAccessories = false }` -> override item field `set = "iron"` (or `setOverrides.<itemId> = "iron"`). Tooltip gets a "Set: Iron (3/4)" section using the existing collapsible tooltip sections. **Out of scope:** set abilities, accessory sets, new saved data (derived from equipped slots each time), new UI frames. **Verification:** equip 2 iron pieces: attribute breakdown for Defense contains source `set:iron` = tier-2 value; 4 pieces: tier-4 replaces tier-2 (no double count); unequip one piece: drops to tier-2; swap a piece for a non-set one: bonus removed; relog restores. **Placeholders needed:** none. **Keybind:** none.
- **Risk:** Double-applying a bonus on swap/relog if the set source is not cleared via the same slot id before re-applying.

### 2. Bestiary (M)
- **Pitch:** Every mob you kill fills a bestiary entry. Hit kill milestones to earn permanent damage and magic-find bonuses against that creature type.
- **Why now:** Seven mobs with their own loot landed in 3.63.0/3.70.0 but a kill is forgotten the moment the loot drops; the Collections page and `CollectionRewards.register` already solve "tiers -> permanent reward".
- **Spec:** Goal: persistent per-enemy kill counts with tiered rewards. Files: `Shared/Modules/Stats/BestiaryConfig.lua` (new), `Server/Stats/BestiaryService.lua` + `BestiaryInit.server.lua` (new), hook in `Server/Combat/LootService.lua` `reward()` (one call), `Server/Data/SkillsDataManager.lua` `PROFILE_TEMPLATE._Bestiary = {}` (Reconcile backfills), `Shared/Modules/Menu/Pages/BestiaryPageModule.lua` (init/open/close/reset; reuse `GridMenuModule` and `TooltipModule`; cloned from the Collections page template in Studio), `CentralizedMenuController` (one page entry), RemoteEvent `BestiaryUpdated` (server -> client only, no client input). Config: library `BestiaryConfig.tiers = { 10, 50, 250, 1000 }` and `BestiaryConfig.rewards.default = { [1] = { type = "damageVs", pct = 1 }, [3] = { type = "gameStat", attr = "MagicFind", flat = 1 } }` -> type `BestiaryConfig.families.undead = { enemies = { "skeleton_grunt" } }` -> override `BestiaryConfig.enemies.slime_blob = { tiers = { 5, 25, 100 }, rewards = { [1] = { type = "damageVs", pct = 2 } } }`. `damageVs` is a new `CollectionRewards.register` type read by `DamageService` as a multiplier against `EnemyType`. Notify via `NotifyService` on tier-up. **Out of scope:** drop-rate display of unseen drops, bosses, per-weapon stats. **Verification:** kill a `slime_blob` x5 via execute_luau: `_Bestiary.slime_blob.kills == 5`, tier 1 claimed once and `damageVs` reward visible in attribute breakdown; second claim attempt is a no-op; unknown enemy type creates no entry; relog keeps counts; damage vs slime is x1.02 and vs others unchanged. **Placeholders needed:** page icon, tier-up sound slot. **Keybind:** none (menu page).
- **Risk:** Tying damage to enemy type touches the hot path in `DamageService`; the multiplier lookup must stay cached per player.

### 3. Potions & Food (M)
- **Pitch:** Eat or drink consumables from your hotbar for timed buffs: regeneration, strength, speed. Active buffs show on the status line so you can plan fights around them.
- **Why now:** The `consumable` item category and `AddTempBonus` already exist but are unused, mobs now drop materials (Slime Blob, Spider Scout, Cinder Imp, Void Wisp), and combat got harder with the new AI (3.74.1), so a prep layer fits.
- **Spec:** Goal: right-click uses a held consumable; the server validates and applies timed buffs. Files: `Shared/Modules/Inventory/Items/Defs/Consumables.lua` (new defs file, registered in the Items index), `Shared/Modules/Inventory/ConsumableConfig.lua` (new), `Server/Inventory/ConsumableService.lua` + init (new, RemoteEvent `UseConsumable` carrying only an item id string), `Client/Inventory/InventoryController.client.lua` (send intent on RMB for category consumable), `Server/Data/AttributeStatManager.lua` (call `AddTempBonus`, no change expected), `ActionBarService.show` for the "Regeneration II - 0:45" line. Config: library `ConsumableConfig.library.default = { useTime = 1.2, cooldown = 1, consume = 1, sound = "eat" }` -> type `ConsumableConfig.types.potion = { useTime = 0.8, sound = "drink" }, types.food = {...}` -> override `ConsumableConfig.items.speed_potion = { effects = { { attr = "Speed", mode = "flat", amount = 20, duration = 120 } } }`; instant effects `{ kind = "heal", amount = 50 }` / `{ kind = "mana", amount = 40 }` go through `ResourceService`. Same item re-use refreshes the timer instead of stacking; strongest of the same attr wins. Other players see a particle burst via `EnemyFX`-style FX preset keyed in config. **Out of scope:** brewing/crafting (reuses Workbench idea later), saved active buffs across relog, new HUD frames beyond a status line. **Verification:** give 3 speed potions with `/give`: use one -> count 2, `ListTempBonuses` contains Speed +20 with ~120s left; use again -> timer refreshed, not doubled; use during cooldown -> rejected, count unchanged; client sends an unknown id or a string for count -> rejected; buff expires -> attribute breakdown drops it; death clears buffs. **Placeholders needed:** drink/eat sounds, three item icons (Minecraft potion sprites via `fetch_icons`). **Keybind:** none (RMB while holding; confirm weapons are never equippable consumables).
- **Risk:** RMB is already an ability key on weapons, so the client must route RMB by held item category and never double-fire.

### 4. Boss: The Rustblade Warden (L)
- **Pitch:** A giant armoured Warden guards a ruin on the island; its health bar crowns the screen and it changes tactics at 66% and 33%. Beat it for rare, guaranteed-pool loot and a big Combat XP payout.
- **Why now:** `rustblade_knight.phases = nil -- RESERVED`, `EnemyAI` and `EnemyAttacks` (combo/lunge/slam/parry) just shipped in 3.74.1, the tag system supports a `boss` look, and `ZoneConfig.ZONES` is empty, so there is nowhere to go to fight something big.
- **Spec:** Goal: a phase-driven boss built from the existing mob pipeline. Files: `Shared/Modules/Combat/EnemyConfig.lua` (phases, boss enemy entry, boss dropTable), `Server/Combat/EnemyAI.lua` (read `phases` and swap the attack set / speed per HP threshold, fire a `PhaseChanged` hook), `Server/Combat/EnemyAttacks.lua` (one new kind, `summon`, that spawns existing `EnemyType` minions via `EnemyService`), `Server/Combat/EnemyTags.lua` (apply `enrage` on phase 3 using the existing API), `Server/Combat/LootService.lua` (per-contributor loot from `DamageTracker`, so everyone who dealt damage gets a personal roll), `Client/Combat/EnemyNameplateController.client.lua` (boss variant of the plate pinned top-screen, cloned from a template added to `ReplicatedStorage.GUI`), `Shared/Modules/Config/ZoneConfig.lua` (add the Warden's ruin zone), `Shared/Modules/Config/NameplateConfig.lua` (boss look). Config: library `EnemyConfig.phaseLibrary.standard = { { at = 1.0, attacks = "base" }, { at = 0.66, attacks = "set2", speedMult = 1.15 }, { at = 0.33, attacks = "set3", tags = { "enrage" }, summon = "slime_blob" } }` -> type `EnemyConfig.enemies.rustblade_warden.phases = "standard"` with attack sets `enemies.rustblade_warden.attackSets = { base = {...}, set2 = {...}, set3 = {...} }` -> override `enemies.rustblade_warden.phaseOverrides[3] = { summon = "skeleton_grunt", count = 2 }`. Boss drops: `dropTables.warden_loot` with a guaranteed pool plus rare chance entries, MagicFind applied as for mobs. **Out of scope:** arena doors/instances, party scaling, new models (uses the knight rig scaled via config), saved boss cooldowns. **Verification:** spawn the Warden via execute_luau, set Health to 65% -> `Phase` attribute == 2 and attack set switches (log shows set2 ids only); 32% -> `Phase` == 3, `Tag_enrage` attribute present, minions spawned equal configured count; phases never regress when healed; two players hit it -> both receive a personal drop roll, a non-contributor does not; boss respawns after configured seconds; leash reset restores `Phase` 1 and full health. **Placeholders needed:** boss model/rig tweaks, phase-change roar and music sound slots, boss plate template, arena zone part. **Keybind:** none.
- **Risk:** Phase switching mid-attack in `EnemyAttacks` can leave a telegraph or windup running into the wrong set; transitions need to wait for the recover step and use a generation counter.

## Recommendation
Ranking: 3 (Potions & Food), 2 (Bestiary), 1 (Armor Set Bonuses), 4 (Warden). Build **Potions & Food** first: it turns an existing but dead item category and an existing temp-bonus API into a visible, SkyBlock-feeling gameplay layer with almost no new architecture. It also gives mob materials a purpose right now and sets up the consumable defs that a future Workbench would craft. If you want a warm-up, ship Armor Set Bonuses first since it is a tiny change.
