- Why now: 3.86.0 put real gear and levels on ten mobs and 3.77.0 made loot fly out, but there is no goal tying them together; NexusConfig already reserves a quest task and WalletService.add has a free sources label.

- Spec:

- Goal: server-rolled kill contracts with progress, claim and re-roll.

- Files: src/Shared/Modules/Config/ContractConfig.lua (new), src/Server/Stats/ContractService.lua (new), a hook next to LootService.reward in src/Server/Combat/EnemyService.lua, src/Server/Data/SkillsDataManager.lua (PROFILE_TEMPLATE._Contracts), a Nexus-menu page module in src/Shared/Modules/Menu/Pages using GridMenuModule.

- Config shape: ContractConfig.library (slots = 3, rerollSeconds, rewardCurve by tier) -> types.kill ({ enemy = "<EnemyConfig key>", count = {10, 30} }) -> contracts.<id> override (custom count, bonus item reward, minLevel). Reward fields: coins, xp = { skill = "Combat", amount }, nexus.

- Saved: _Contracts = { active = {}, claimed = 0, rerollAt = 0 }, backfilled by Reconcile. Server rolls and counts kills; client only sends ClaimContract(slot) / RerollContract(slot), type-checked and rate limited (RateLimiter).

- Out of scope: non-kill contract types, party sharing, a world-space board model.

- Verification: after ContractService.roll the profile has 3 active entries each naming a real EnemyConfig key; killing a matching mob raises progress by 1 and a non-matching mob changes nothing; claiming before count is reached returns false and leaves Coins unchanged; claiming at count raises WalletService.get by the configured coins and Nexus XP by the configured amount; rejoin keeps progress; a second claim of the same slot fails.

- Placeholders needed: board icon, claim sound (empty ids are skipped).

- Keybind: none (menu page).

- Risk: double-credit of a kill (kill hook plus loot hook) or claim races; one guarded claim function with a claimed flag avoids it.

- Pitch: Roll into an attack at the last moment and the hit is "Perfectly dodged": you get stamina back and a bright flash. Skilled rolling pays off against the knights' telegraphs.

- Why now: the dodge roll shipped in 3.83.0 with i-frames and 3.85.0 added its FX, but a hit during i-frames is just ignored in DamageService.hurtPlayer.

- Spec:

- Goal: detect an enemy hit landing within a short window after roll start and reward it.

- Files: src/Shared/Modules/Stats/MovementConfig.lua (add dodge.perfect), src/Server/Combat/DamageService.lua (branch in the i-frame check), src/Server/Stats/MovementService.lua (small perfect(player) function that refunds stamina and notifies).

- Config shape: dodge (library) -> dodge.types.<type> -> new perfect = { window = 0.12, staminaRefund = 25, cooldown = 1, color = "#55FFFF", text = "PERFECT" }, so a heavy dodge type can override window or refund per field. Window is measured as now - (DodgeUntil - iframes).

- Out of scope: slow-motion, damage buffs, counter attacks, new animations.

- Verification: roll and take a hit 0.05 s later: damage dealt is 0 and Stamina rises by staminaRefund (capped at max); a hit 0.2 s into the roll deals 0 with no refund; two perfects within cooldown refund once; no refund when perfect is nil in config.

- Placeholders needed: perfect-dodge sound and flash colour (silent until set).

- Keybind: reuses F (existing).

- Risk: the window is measured in server time against client-started rolls, so latency can make it feel stricter than it looks; keep the default window generous.

- Pitch: Open the Warp Map in the Nexus menu and teleport to any zone you have already visited. A short cast time keeps it from replacing running in a fight.

- Why now: the WarpMap button is already in the Nexus bottom row (3.85.3) but opens nothing, and ZoneInit already knows the zones.

- Spec:

- Goal: persistent unlocked warp points and server-validated teleport.

- Files: src/Shared/Modules/Config/ZoneConfig.lua (add warp fields), src/Server/World/ZoneInit.server.lua (unlock on enter, WarpRequest handler), src/Server/Data/SkillsDataManager.lua (PROFILE_TEMPLATE._Warps), a page module using GridMenuModule.

- Config shape: ZoneConfig.warp.library (castSeconds, cooldown, coinCost, blockedAfterDamageSeconds) -> zones.<id>.warp = { spawn = "<Workspace part name>", unlockedByDefault = false } -> per-zone override of any library field.

- Saved: _Warps = { unlocked = {} }, backfilled by Reconcile. Client sends only the zone id; server checks unlocked, cooldown, cast not interrupted by damage or movement, and Coins via WalletService.spend, then pivots the character.

- Out of scope: warp-in animation, cross-server teleport, party warps.

- Verification: entering a zone adds its id to _Warps.unlocked; requesting a locked zone returns false and does not move the character; an unlocked request teleports within castSeconds +/- 0.5 s and charges coinCost; taking damage during the cast cancels it with no charge; spamming the remote hits the rate limit.

- Placeholders needed: per-zone map icons, whoosh sound.

- Keybind: none (menu button).

- Risk: spawn parts are authored in Studio (not Rojo), so a missing part must fail soft with a warning, not teleport to the origin.

- Pitch: Hatch pets from mob drops and rare eggs, equip one, and watch it follow you. Pets level from your skill XP and add stats.

- Why now: the stat pipeline (Sources.lua) and drop tables are mature, NexusService has a free misc category, and the item registry already supports drop rarities; pets are the classic SkyBlock long-term chase.

- Spec:

- Goal: collectable, levelling companions that grant stats and are visible to everyone.

- Files: src/Shared/Modules/Config/PetConfig.lua (new), src/Server/Stats/PetService.lua (new), src/Shared/Modules/Stats/Sources.lua (register a pet source type), src/Server/Data/SkillsDataManager.lua (_Pets), src/Client/World/PetFollowController.client.lua (new), a Pets page module, and drop-table entries in EnemyConfig.lua.

- Config shape: PetConfig.library (levels = 100, xpCurve, followDistance, bob) -> types.<pet id> ({ rarity, skill = "Combat", stats = { Strength = {perLevel = 0.5} }, model = "<ReplicatedStorage template>" }) -> overrides.<petId> for a per-pet tweak; mobs add { kind = "item", id = "pet_egg_slime", chance = 0.005 } in their drop tables.

- Saved: _Pets = { owned = { {id, xp} }, active = nil }, backfilled by Reconcile. Server grants pet XP from SkillsDataManager.AddXP for the pet's skill, writes player attribute ActivePet; every client renders followers from that attribute (visible to others). Equip/unequip remote type-checks the id and rate limits.

- Out of scope: pet items/held perks, merging, a pet shop, pet abilities.

- Verification: granting an egg adds an owned pet at level 1; equipping sets ActivePet and adds the pet's stat to AttributeStatManager.GetFinalValue; gaining skill XP in the pet's skill raises pet xp, other skills do not; unequipping removes the stat; a second player's client spawns a follower for the first player's ActivePet; rejoin keeps owned pets and xp.

- Placeholders needed: pet models/icons, hatch sound (a plain cube follower is used until models exist).

- Keybind: none (menu page).

- Risk: scope - pets touch drops, stats, saves, rendering and a menu; build config + stat + save first and the follower visuals last.

Rank: 1 Hunt Contracts, 2 Perfect Dodge, 3 Warp Map, 4 Pets. Build Hunt Contracts first: it needs no Studio-authored world content, reuses the kill hook, wallet, XP and Nexus pipelines, and gives every existing mob a purpose. Perfect Dodge is a cheap follow-up that deepens the combat Nate just finished.

                  /fia-feature Hunt Contracts (M): a contract board in the Nexus menu. The server rolls 3 kill contracts per player ("Slay N <enemy>"), counts kills, and pays Coins, Combat XP and Nexus XP on claim.

Goal: give every existing mob a purpose with a server-authoritative kill-contract loop.

Files:
- src/Shared/Modules/Config/ContractConfig.lua (new)
- src/Server/Stats/ContractService.lua (new): roll, progress, claim, re-roll; remotes ClaimContract(slot) / RerollContract(slot) and a ContractsUpdated event; type-check inputs, rate limit with RateLimiter
- kill hook next to LootService.reward in src/Server/Combat/EnemyService.lua (credit the killer once)
- src/Server/Data/SkillsDataManager.lua: PROFILE_TEMPLATE._Contracts = { active = {}, claimed = 0, rerollAt = 0 } (Reconcile backfills)
- a page module in src/Shared/Modules/Menu/Pages using GridMenuModule (init/open/close/reset), opened from a Nexus-menu slot; template frames made in Studio, scripts clone and fill (no Instance.new UI)

Config shape (library -> type -> override):
- ContractConfig.library = { slots = 3, rerollSeconds = 600, rewardCurve = {...} }
- ContractConfig.types.kill = { enemy = "<EnemyConfig key>", count = { 10, 30 } }
- ContractConfig.contracts.<id> = override (custom count, bonus item, minLevel)
- Rewards: coins (WalletService.add, source "contract"), xp = { skill = "Combat", amount } (SkillsDataManager.AddXP), nexus (NexusService.award with the quest/misc category from NexusConfig)

Out of scope: non-kill contract types, party sharing, world-space board, new art.

Verification (text assertions): roll gives 3 active entries each naming a real EnemyConfig key; a matching kill raises progress by 1, a non-matching kill changes nothing; claim before count fails and leaves Coins unchanged; claim at count raises Coins and Nexus XP by the configured amounts; a second claim of the same slot fails; rejoin keeps progress; re-roll respects rerollSeconds.

Placeholders: board icon and claim sound ids are empty (silent). Keybind: none.
