# FI:A ideation - 2026-10-08

Assumptions: no previous report branch existed on origin, so nothing could be repeated. Vault unavailable. Keys checked by grep: Q/R/T/E bound, C/G appear in Client scripts, abilities use RMB/Z/X/C/V; ideas below use no new key.

## What I noticed
- **Skills other than Combat have no gameplay loop.** `SkillsDataManager.AddXP` is only fed by kills (`LootService`, `EnemyConfig.xp`) and the world buttons; Farming/Foraging/Mining/Fishing/Carpentry have XP tables and level rewards (`Stats/SkillsConfig.lua`) but nothing to do.
- **Fortune/Speed/Crit stats have no consumer.** `ProfileConfig.lua` defines MiningFortune, ForagingSpeed, FarmingCritChance etc., but Server only reads Defense, HealthRegen and MagicFind (`DamageService`, `ResourceService`, `LootService`).
- **Materials and Coins have no sink.** `Items/Defs/Materials.lua` (~20 materials) and 5 mobs' `dropTables` (commit 3.63.0, 3.70.0) feed the inventory, but the Crafting menu is "Coming Soon" (`CentralizedMenuController` CraftingMenu) and `CoinsConfig.sources` is documentation only. The `recipe` reward type only writes ids into `_Rewards.recipes` (`RewardBehaviors.lua`).
- **Momentum is combat/enemy depth:** AI state machine and attacks (3.74.1), death FX (3.73.x), nameplate tags (3.71-3.72), multi-ability weapons (3.69.0), loot and drop tags (3.59-3.74). `EnemyConfig` already has `tags` ("boss") and a reserved `phases` field, and `ZoneConfig.ZONES` is empty.

## Ideas

### 1. Elite Variants (S)
- **Pitch:** Now and then a mob spawns as a glowing Elite with a gold tag, more health and better loot. Spotting one makes a fight worth taking.
- **Why now:** Nameplate tags (3.71/3.72) and the loot pipeline (3.59-3.63) are ready but every spawn of a type is identical; MagicFind has few sources.
- **Spec:** Goal: per-enemy chance to roll a variant at spawn. Files: `Shared/Modules/Combat/EnemyConfig.lua`, `Server/Combat/EnemyService.lua`, `Server/Combat/LootService.lua`. Config: library `EnemyConfig.variants.elite = { chance = 0.05, hpMult = 3, damageMult = 1.5, xpMult = 3, dropChanceMult = 2, coinMult = 3, tags = {"boss"}, tint = Color3 }` -> type `enemies.<key>.variants = { "elite" }` -> override `enemies.<key>.variants_override.elite = { chance = 0.02 }`. Server stamps attribute `Variant="elite"`, appends the tag via `EnemyTags.add`. **Out of scope:** new models, bosses/phases, saved data, UI. **Verification:** spawn 200 test rolls via execute_luau: Variant ratio within 0.03-0.07; elite MaxHealth == base x hpMult; kill awards xp x3; `Tag_boss` attribute present; non-listed enemies never roll. **Placeholders needed:** tint only, optional spawn sound slot. **Keybind:** none.
- **Risk:** Level display (`levelInfo`) is computed from stats and may inflate the elite's level badge unexpectedly.

### 2. Workbench & Recipes (M)
- **Pitch:** Open the Crafting menu to turn mob loot and gathered materials into gear. Recipes unlock from skill levels and collections.
- **Why now:** Crafting is "Coming Soon", the `recipe` reward stub already records ids in `_Rewards.recipes`, and 20+ materials pile up unused.
- **Spec:** Goal: server-validated crafting. Files: new `Shared/Modules/Stats/RecipesConfig.lua`, new `Server/Inventory/CraftingService.lua` (+Init), `Shared/Modules/Menu/Pages/CraftingPageModule.lua` (init/open/close/reset contract), `CentralizedMenuController` (wire CraftingMenu), a Remote `CraftItem`. Config: library `RecipesConfig.recipes.<id> = { output = {id, count}, inputs = { {id, count} }, coins = 0, skill = "Carpentry", xp = 25, unlock = "recipe id or nil" }` -> type `RecipesConfig.stations.workbench = { recipes = {...} }` -> override `RecipesConfig.overrides.<id> = { coins = 50 }`. Reuses `_Rewards.recipes`, no new saved field. GUI frames are cloned from Studio templates. **Out of scope:** forge timers, armor upgrades, auctions. **Verification:** give inputs via admin /give, call CraftItem: inputs decremented, output present, XP granted; missing input -> rejected, inventory unchanged; locked recipe -> rejected; spam over rate limit rejected; non-numeric count rejected. **Placeholders needed:** craft sound, menu icon. **Keybind:** none (menu button).
- **Risk:** Removing/adding many Tools hits the known Backpack freeze; must use `InventoryDataManager` batch APIs.

### 3. Island Merchant (M)
- **Pitch:** Talk to the Merchant to sell spare materials for Coins and buy basic gear and supplies. Coins finally buy something.
- **Why now:** Coins (3.60-3.61, `WalletService`) are earned from every kill but there is no sink; `CoinsConfig.sources` already anticipates shops.
- **Spec:** Goal: sell/buy with server-side pricing. Files: new `Shared/Modules/Config/ShopConfig.lua`, new `Server/Data/ShopService.lua`, `Shared/Modules/Menu/Pages/ShopPageModule.lua`, Remote `ShopTrade`. Config: library `ShopConfig.prices.default = { sellFraction = 0.4 }` -> type `ShopConfig.byRarity[rarity] = { buy = 40, sell = 8 }` -> override `ShopConfig.items.<itemId> = { buy = 90, sell = 20 }`; merchants `ShopConfig.merchants.<name> = { stock = {...}, buys = "materials" }`. Merchant is a ProximityPrompt on a Studio model (distance checked server-side). **Out of scope:** auction house, dynamic prices, bank. **Verification:** sell 5 bone -> Coins +5*sell, items -5; buy with insufficient Coins rejected; trade at distance >12 studs rejected; WalletService.add source label "shop". **Placeholders needed:** merchant model, coin sound. **Keybind:** none (ProximityPrompt).
- **Risk:** Sell prices that let players farm Coins faster than intended; needs a sell-price audit.

### 4. Gathering Nodes: Mining & Foraging (L)
- **Pitch:** Swing a pickaxe or axe at ore veins and trees to mine them, earn skill XP and collect resources that regrow after a while. Fortune and Speed stats finally matter.
- **Why now:** Two of six skills only have XP tables; MiningFortune/ForagingSpeed exist in `ProfileConfig` with no consumer, and the drop/loot pipeline (`LootService`, drop tags, stacking) already handles items, stats and Coins.
- **Spec:** Goal: tagged world nodes gathered by tools, server-authoritative. Files: new `Shared/Modules/Config/GatherConfig.lua`, new `Server/World/GatherService.lua` (+Init), extend `LootService` with a `rollTable(player, entries, position)` entry point, tool def category in `Items/Defs/Weapons.lua` (or new `Tools.lua`) with `gather = { skill, power }`, `WeaponController` sends only click intent, `SkillsConfig` unchanged. Config: library `GatherConfig.library.default = { hits = 4, respawn = 30, xp = 5 }` -> type `GatherConfig.types.ore_coal = { skill = "Mining", tier = 1, drops = {{table="coal_ore"}}, hits = 5, respawn = 45, xp = 8 }` -> override `GatherConfig.overrides.<tag>.<nodeName> = { respawn = 20 }`. Fortune adds drop count/chance (`MiningFortune` / 100 as extra rolls), Speed lowers hits needed. Nodes are CollectionService-tagged models in Workspace; depleted state is an attribute + transparency tween, respawn restores it. **Out of scope:** Farming/Fishing/Carpentry, node generation, new saved data, tool durability. **Verification:** hit a node with a tool below its tier -> no damage; N hits -> Depleted attribute true, drops spawn, Mining XP +xp; with MiningFortune set via admin /set drops average rises; respawn after configured seconds; click spam above rate limit ignored; client-sent node/distance >10 studs rejected. **Placeholders needed:** node models/tags, hit & break sounds, ore icons. **Keybind:** none (LMB with tool).
- **Risk:** Hit detection and rate limiting vs. the weapon swing system (`WeaponManager`) may double-fire damage on nodes.

## Recommendation
Ranking: 4 (Gathering), 2 (Workbench), 3 (Merchant), 1 (Elites). Build **Gathering Nodes** first, starting with Mining only: it closes the biggest gap (two skills with zero gameplay and unused Fortune/Speed stats) and creates the materials that Workbench and Merchant then consume. It reuses `LootService` and the layered-config pattern, so most of the work is data plus one service. If an L feels too big for a single session, ship Elite Variants (S) first as a warm-up.
